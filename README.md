# Ship & Commit

Ship & Commit is a consent-based accountability platform and launchpad for Web3 builders on Solana.

- **Launchpad (Auto-Lock):** launch a token on pump.fun in a few clicks. Creator fees are locked in an on-chain escrow (a Privy-managed wallet) and released milestone by milestone.
- **Manual Lock:** already launched? Link your existing pump.fun token, verify you're the dev wallet, and lock your fees behind milestones.
- **Holder voting:** token holders approve completed milestones with signed messages. Missed deadlines redistribute escrowed fees to voters and fuel `$SHIP` buybacks.
- **Utilities:** market-cap milestones (auto-resolved), ASD (automated sell-down), transparent bundler / declared team wallets, creator & holder dashboards, public profiles, vote-reward claims.

Safety model:

- Users keep custody of their own wallets; participation uses signed messages.
- Escrow addresses are generated by the platform (Privy-managed for Auto-Lock). Releases are explicit, audited, on-chain transfers.

## Stack

Next.js 14 (App Router) · TypeScript · Solana (`@solana/web3.js`, wallet-adapter) · Postgres (`pg`) · Privy server wallets · Railway.

## Local development

```bash
cp .env.example .env.local     # fill in the values you need
npm install
npm run dev
```

Requirements: Node 20.18+, a Postgres `DATABASE_URL` (tables are created automatically on first use), a Solana RPC URL. Set `CTS_MOCK_MODE=1` to run without a database (in-memory demo data; never in production).

## Deploying to Railway

The project deploys as one web service plus a Postgres database:

1. Create a Railway project with a **Postgres** service and a **web** service (this repo).
2. Set the variables from `.env.example` on the web service. `DATABASE_URL` should reference the database: `${{Postgres.DATABASE_URL}}`.
3. Deploy (`railway up`, or connect the GitHub repo). `railway.json` configures the start command and the `/api/healthz` healthcheck.
4. Set `APP_ORIGIN` to your public URL (a custom domain and the Railway domain can both be listed, comma-separated).
5. In the Privy dashboard, point the webhook at `https://<your-domain>/api/webhooks/privy`.

Notes:

- **Background jobs** (market-cap milestone resolution, reward normalization, ASD, bundler snapshots, housekeeping) run in-process via `instrumentation.ts` / `app/lib/boot.ts`, guarded by Postgres advisory locks so replicas never double-run a job. They need `CRON_SECRET`.
- **Images** (token icons/banners, avatars) are stored in Postgres and served from `/api/assets/*`. Set `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` only if you prefer Supabase Storage.
- **Browser RPC** goes through the same-origin `/api/rpc` proxy, so the server RPC key never reaches the browser.

## Repo structure

- `app/` — Next.js app + API routes (`app/api/**`), shared libs in `app/lib/**`
- `docs/` — platform overview (rendered at `/docs/platform-overview`)
- `public/` — static assets and branding
- `supabase/migrations/` — legacy SQL, kept for reference; the app creates its own tables at runtime

## Custody disclosure

Escrow secrets for non-Privy commitments are stored server-side, encrypted at rest with `ESCROW_DB_SECRET`. Auto-Lock escrows are Privy-managed wallets signed through the Privy API.
